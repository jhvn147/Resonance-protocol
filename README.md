Resonance Protocol: Complete Technical Specification and Implementation

1. Introduction

Centralised platforms rely on data harvesting, continuous user tracking, and attention-extraction algorithms. This project establishes the **Resonance Protocol**, a decentralised, peer-to-peer web application designed to connect individuals seeking assistance with peers offering expertise without advertisements, accounts, or financial transactions.

2. Purpose

The architecture eliminates commercial noise and privacy vulnerabilities present in standard messaging environments. By replacing public broadcast feeds with direct, intent-based signaling, the system enables learners and tutors to establish ephemeral, secure sessions. It removes profit incentives, user tracking, and metadata collection from the peer-to-peer exchange process entirely.

3. Goal

The structural targets of this protocol comprise:

* **Zero Infrastructure Cost:** Operating entirely on static file hosting via GitHub Pages with zero database overhead or server maintenance expenses.
* **Absolute Privacy:** Utilizing browser-native WebRTC protocols and cryptographic key pairs instead of emails, phone numbers, or persistent user profiles.
* **Safety by Design:** Hard-disabling webcams and file uploads at the protocol level while implementing client-side cryptographic blacklisting to filter malicious participants locally.
* **Frictionless Problem Solving:** Providing a streamlined environment equipped with an encrypted audio channel and a low-bandwidth vector whiteboard.

4. How to Use

The platform operates without user registration, downloads, or backend setup.

1. **Access the Interface:** Navigate to the published web address in any standard browser (Chrome, Firefox, Safari, or Edge) on desktop or mobile devices.
2. **Review Your Active Peer ID:** Upon loading the page, the sidebar automatically generates and displays your unique alphanumeric **Cryptographic Peer ID** (e.g., `peer-8f3a9b`). Share this string directly with a peer via any auxiliary channel if connecting manually.
3. **Define Intent (The Beacon):**
* In the **Seeking** text box, enter the specific problem or concept requiring assistance (e.g., differential equations or mechanical fluid dynamics).
* In the **Offering** text box, enter the domain of expertise available to share (e.g., technical college engineering mathematics).


4. **Broadcast:** Click the **Broadcast Beacon** button to transmit the intent packet across the local signaling relay network.
5. **Join a Session:**
* To connect directly with a peer, paste their unique alphanumeric string into the **Session / Peer ID** input field on the left sidebar.
* Click **Join Session** to execute the direct WebRTC handshake.


6. **Collaborate:** Speak naturally over the encrypted audio link while sketching diagrams, force vectors, or equations on the shared whiteboard canvas.
7. **Terminate:** Click **End Session & Wipe** to disconnect the audio stream, clear the canvas, and destroy all temporary session keys instantly.

5. UI Element-by-Element Explanation

The interface divides into two main panels: a left configuration sidebar and a right workspace canvas. Every component functions as follows:

* **Header Title ("Resonance Protocol"):** Displays the name of the decentralised application.
* **Status Indicator Dot & Text:** Displays the real-time connection state of the browser node (e.g., *Offline / Standby*, *Beacon Broadcasted*, or *Session Connected*).
* **Your Active Peer ID Card:** Displays the local cryptographic identifier generated by the browser for manual session pairing.
* **Seeking (Problem) Textarea:** Accepts a short text description defining the technical difficulty or question requiring a solution.
* **Offering (Expertise) Textarea:** Accepts a short text description defining the skills or subject matter available to share.
* **Broadcast Button:** Triggers the transmission of the user's intent packet to the decentralised signaling relay network.
* **Session / Peer ID Input:** Accepts the unique alphanumeric cryptographic string provided by a matching peer during manual connection handshakes.
* **Join Session Button:** Initiates the direct peer-to-peer WebRTC connection using the entered session identifier string.
* **Clear Canvas Button:** Erases all vector drawings from the local whiteboard surface.
* **Whiteboard Canvas:** A high-performance HTML5 rendering area designed for drawing vector strokes, diagrams, and mathematical models with minimal bandwidth usage.
* **Mute/Unmute Mic Button:** Toggles the local audio track state for the browser microphone.
* **Voice Status Indicator:** Displays whether the audio channel is inactive, muted, or actively streaming.
* **End Session & Wipe Button:** Instantly terminates media tracks, closes the peer connection, clears the whiteboard, resets input fields, and shreds temporary cryptographic state data from memory.
